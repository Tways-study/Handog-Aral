# Release checklist

Go-live steps for Handog Aral. Nothing here needs a secret written into the repo: keys live in Vercel (and in a local `.env.local` that is git-ignored).

## 1. Vercel project (web)

- [ ] Import the repo into Vercel (framework preset: Next.js). Production branch: the branch you release from.
- [ ] Set the environment variables from `.env.example` for **Production** (and Preview if you want previews to work):
  - `GEMINI_API_KEY` (server only), optional `GEMINI_MODEL` (defaults to `gemini-flash-latest`)
  - `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` (the proxy fails closed with 503 in production without them)
  - `ALLOWED_ORIGINS` only if another web origin must call the proxy (the Android origins `https://localhost` and `capacitor://localhost` are always allowed)
  - `NEXT_PUBLIC_SITE_URL` = the production origin (used for the social-card image URLs)
  - Leave `NEXT_PUBLIC_API_BASE` empty for the web build
- [ ] Create an Upstash Redis database (free tier is enough) and copy its REST URL and token into the two variables above.
- [ ] Add the custom domain in Vercel, then update `NEXT_PUBLIC_SITE_URL` to match and redeploy.
- [ ] Build command stays `npm run build`; `public/tesseract/` is generated by `scripts/copy-tesseract.mjs` during `prebuild` (needs network at build time).

## 2. Post-deploy smoke checks (replace `$URL`)

```bash
curl -s $URL/api/health                                   # {"ok":true}
curl -sI $URL/ | grep -iE "x-frame|content-security|nosniff|referrer|permissions"   # security headers present
curl -sI $URL/serwist/sw.js | grep -iE "cache-control|service-worker-allowed"       # no-cache, Service-Worker-Allowed: /
curl -s $URL/manifest.webmanifest | head -c 300           # id, shortcuts, screenshots
curl -sI $URL/opengraph-image.png | head -1               # 200
```

- [ ] Explain with a real key: `curl -s -X POST $URL/api/explain -H 'content-type: application/json' -d '{"word":"brave","sentence":"The brave fox ran.","language":"hiligaynon"}'` returns a word explanation (not 503/502).
- [ ] OCR with a real key: scan a page in the app online and confirm text comes back (the proxy path, not the local Tesseract fallback).
- [ ] Rate limit: send 31 explain requests inside a minute from one IP; the 31st returns 429. (`explain` allows 30/min, `ocr` 6/min.)
- [ ] CORS from the Android origin: `curl -s -i -X OPTIONS $URL/api/explain -H 'Origin: https://localhost' -H 'Access-Control-Request-Method: POST'` returns 204 with `Access-Control-Allow-Origin: https://localhost`; an unknown origin gets 403.
- [ ] Open the site on a phone: install it (Chrome: menu, Install app; iOS Safari: Share, Add to Home Screen), go offline, and confirm Home, a book and a saved word still open, and an uncached page shows the in-world offline page.
- [ ] Open a missing URL (`/nope`) and confirm the owl "page not found" page appears with a way home.

## 3. Android (Capacitor)

- [ ] `NEXT_PUBLIC_API_BASE=https://<your-production-origin> npm run build:android` (static export, no service worker; do not run it while another `next build` shares `.next`/`out`).
- [ ] `npx cap open android`, then build and run from Android Studio. Debug on a real device first.
- [ ] Device test list:
  - Camera: first scan asks for permission; accept, capture, text appears; deny and confirm the calm "camera unavailable" path with the gallery/typing alternative
  - Scan while offline falls back to local Tesseract (the offline pack must have been downloaded once online)
  - Text-to-speech reads a sentence and a single word in English; the speed setting is respected; stopping works
  - Android back button: from a pushed screen it goes back, from Home it leaves the app (no trap)
  - Word explanations work online through the deployed proxy (CORS) and offline from the curated dictionary
  - Rotate the phone; large font size and dyslexia font still fit
  - Install button is hidden in the Settings screen (it must not appear inside the Capacitor app)
- [ ] Bump `versionCode`/`versionName` in `android/app/build.gradle` and sign a release bundle for Play.

## 4. Quality gates before tagging

```bash
npm run typecheck && npm run lint && npm test
NEXT_DIST_DIR=.next-e2e npm run build && npx playwright test        # includes e2e/a11y.spec.ts (axe, WCAG 2.1 A/AA) and security-headers
# Lighthouse (mobile profile) against a production build:
npx -y lighthouse http://localhost:3200/ --only-categories=performance,accessibility,best-practices,seo --quiet
```

Targets: Accessibility, Best Practices and SEO 100; Performance 90+ with LCP at or under 2.5 s on the throttled mobile profile. Regenerate the social card with `node scripts/gen-og.mjs` and the install screenshots with `node scripts/gen-screenshots.mjs` after any visual redesign.

## 5. Privacy note (for the store listing and a parent-facing page)

- There are no accounts and no sign-in. Name, language, progress, saved words and settings stay on the device (IndexedDB/localStorage). Nothing is uploaded to identify a child.
- When online, the server proxy sends Google Gemini only what is needed for the request: the tapped word and its sentence (explain), or the cropped page image (OCR). Image bytes are processed in memory, are not stored by the app, and are not logged by it. Requests are rate-limited per IP using Upstash (an IP-derived key, not stored with content).
- Offline, everything runs locally (curated dictionary, on-device Tesseract). The service worker never caches `/api/*`.
- Camera access is used only to photograph a page when the child presses scan. No analytics or ad SDKs are included.
- Review Google's current Gemini API data-use terms for your tier before publishing the privacy policy.

## 6. Known gaps (from docs/v3-plan.md)

- The 2,000-word offline dictionary is not built; the app ships ~280 curated words plus the online dictionary. Generated entries need a native-speaker review.
- Real Gemini calls have not been exercised in CI; the proxy is covered by mocked tests and guard-rail smoke tests. Do the step 2 checks with a real key.
- On-device checks (camera, native TTS, back button, the service-worker update prompt on a real browser) have not been run.
- Hiligaynon and Tagalog AI explanations are not human-reviewed; the UI labels their source.
